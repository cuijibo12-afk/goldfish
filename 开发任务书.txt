## 产品边界（必须遵守）
1. 只供一个人长期使用，暂不考虑公开发布、商业化、多租户和复杂账户体系。
2. 宿主是 DeepSeek Harness（DSH），重点是每次模型推理前“自动向主对话可见上下文注入相关记忆”，不是要求聊天 Agent 主动调用记忆工具。应使用宿主公开 API / 生命周期，验证其当前版本行为。
3. 不规定 AI 固定人格或语言风格，不生成“你必须表现得怎样”的大段人格指令；保留模型自身的表达倾向。用户提出“希望 AI 以后怎样对待我”，写为用户画像子类“交互期望”（描述性、有来源），单次抱怨归入互动反馈，AI 画像只记录有证据的已表现行为；这三者不可互相冒充。
4. 原话证据不凭模型推断改写。概括保留细节，主题不取代概括；概括↔概括的可解释关联是核心能力之一。模型提出的关联猜测要标记，不得生成伪因果。
5. 召回同时考虑内容/语义、主题、时间，而不是只用主题召回、时间作兜底；再做有界图谱扩散（最多 2 跳，可调）。一句普通线索可以唤起数段相关经历，但最终注入应精炼，避免强行心理分析。
6. DSH 本身已有会话压缩。金鱼只补充“当前有效上下文中缺失的长期信息”，尽量不重复注入；但绝不能因“过去注入过”就永久禁止，压缩后丢失的事实必须允许补充。
7. 记忆整理 LLM 与 Embedding 可分别配置为本地（Ollama / LM Studio 等）或云端 OpenAI-compatible 接口，支持混合方案；接口失效不影响 DSH 正常聊天。无配置不偷偷联网。不得将 API Key 写入源码、日志或示例提交。
8. 本地服务、数据库、原始聊天日志和模型调用都属于用户敏感数据；对外传输需要显式配置，尽量本机运行，谨慎测试数据与日志脱敏。

## 当前项目现状
- Python 后端：goldfish/engine.py、consolidate.py、providers.py、server.py；本地 SQLite；可选 Ollama / 兼容 OpenAI 的 LLM 与 Embedding 适配；轻量 REST 接口。
- DSH 桥接草案：dsh-plugin/index.js、package.json、cordis.patch.yml；通过 agent/pre-step 与 session/event 设计推理前注入和历史事件采集。
- 测试：tests/ 与 dsh-plugin/test.mjs；多为模拟，不等于真实 DSH 兼容。不能据此声称已上线。
- 必须首先检查：DSH Hook 与 current core types 是否匹配，事件 payload、事件时序、source.kind、role、消息注入位置、取消与重试的持久化语义、deriveMessages() 结果是否反映压缩后的真实有效上下文。

## 分阶段开发与交付
阶段 A（必做）：审计现有源码并运行原测试；检查重复写入、事务原子性、并发锁、队列失败重试、事件丢失、重复 summarize、证据 ID 校验、DB 迁移、SQL 安全、错误日志、异步退出，以及概括关联质量。记录真实问题并修复；先建立 Git 基线，按阶段提交。
阶段 B（最高优先）：在隔离 DSH profile 实际安装；验证每轮前的主动召回、主对话可见注入、真实人类发言和实际助手回复捕获、压缩前后重复注入判定、取消/失败/重试场景。插件不能误把自己注入的内容再次作为用户事实保存；后端关闭不得破坏正常聊天。
阶段 C：分别接通一个真实 Ollama LLM+Embedding 和一个云端 OpenAI-compatible LLM（云端测试只有在用户提供凭据后进行）；验证模型切换、embedding 重新索引、失败回退及真实中文聊天整理质量。缺少模型或凭据，明确说明仅完成模拟测试。
阶段 D：优化“概括—主题—时间—关系网络”检索，加入可观察的召回调试数据（每轮为何命中/跳过哪些记忆、关系边理由与证据、注入长度、上下文覆盖判定），并准备小规模人工评测。
阶段 E：封装个人可用的最简安装/启动/备份/恢复说明与自动化回归测试。不要先做 GUI、商业市场、多人系统或复杂部署。

## 必须通过的验收场景
1. 连续 5 轮讨论同一件经历，能避免无意义重复注入。
2. DSH 压缩后，丢失的细节可再次注入；摘要已有的事实无需重复塞入。
3. 只提过去一个不显眼的细节，能越过高度压缩主题召回原概括，并联想到另一件有证据的经历。
4. 问“去年/上个月/当时”等带时间条件问题，不能把不同阶段的观点简单覆盖或混淆。
5. 因为两件事有关联，不得擅自断言其中一件导致另一件。
6. “我希望你不要总附和我”归入用户交互期望；不变成 AI 画像“AI 天生爱反驳”。
7. 用户说“你刚才回答太机械”先记互动反馈，不凭一次评价永久改写风格。
8. 模型或金鱼服务不可用时，DSH 聊天仍可正常进行；原始事件暂存并能补录，不能静默丢失。
9. 取消推理或模型重试不应错误确认某条记忆已经进入上下文，也不能造成重复入库。
10. 仅提供本地模型配置时，不把用户私密聊天发送到云服务。
11. 能追查每条概括及关联所依据的原话，拒绝缺乏证据的用户画像事实。
12. 同一问题关闭/开启关系扩展，对比准确性、误联想、延迟和注入量。
