金鱼 Goldfish Memory v0.3：本地模型 / 云端模型配置说明
====================================================

一、模型负责哪些任务？
1. 整理模型（LLM）：提取概括、主题、关系与画像，并复核关系类型。显式开启语义召回后，也判断问题意图和当前上下文覆盖。
2. 向量模型（Embedding，可选）：将概括与用户问题转换为语义向量，补充关键词/时间/主题召回。
金鱼配置不会替换 DSH 的主聊天模型，DSH 继续使用自己配置的聊天模型。

二、完全本地免费使用（需要安装 Ollama，且硬件能运行所选模型）
在 PowerShell 中执行（模型名请换成 ollama list 里真正安装的名字）：

$env:GOLDFISH_LLM_PROVIDER="ollama"
$env:GOLDFISH_LLM_MODEL="qwen3:4b"
$env:GOLDFISH_EMBED_PROVIDER="ollama"
$env:GOLDFISH_EMBED_MODEL="bge-m3"
python -m goldfish.server --port 18320

模型未下载时，先安装 Ollama，并用 ollama pull <model> 拉取对应模型。
默认 Ollama 地址：http://127.0.0.1:11434
服务默认本机监听地址：http://127.0.0.1:18320

三、云端 API（通常按调用量计费）

$env:GOLDFISH_LLM_PROVIDER="openai"
$env:GOLDFISH_LLM_URL="https://YOUR_PROVIDER/v1"
$env:GOLDFISH_LLM_MODEL="YOUR_MODEL"
$env:GOLDFISH_LLM_API_KEY="YOUR_KEY"
python -m goldfish.server --port 18320

重要：必须填写兼容 Chat Completions 协议的 API；不能直接填普通聊天网页 URL。
Embedding 可不设置，保持字面/主题/时间/关联检索。

四、混合模式（推荐尝试）

云端 LLM 负责长对话整理与建立关系；Ollama 本地 Embedding 负责查询与概括向量化。
先设置“三”的四项，再设置：

$env:GOLDFISH_EMBED_PROVIDER="ollama"
$env:GOLDFISH_EMBED_MODEL="bge-m3"

也可以反过来：本地 LLM + 云端 Embedding，不过这会将概括和每次搜索问题发送到云端。

五、LM Studio / 其他本地 OpenAI-compatible 模型服务

$env:GOLDFISH_LLM_PROVIDER="openai"
$env:GOLDFISH_LLM_URL="http://127.0.0.1:1234/v1"
$env:GOLDFISH_LLM_MODEL="你本地服务中的真实模型名"

Embedding 的 URL、模型同理；本地服务必须确实提供 /v1/embeddings 接口。

六、切换和排错

1. 修改环境变量后，重启金鱼 Python 服务（目前没有热切换/UI）。
2. 访问 GET http://127.0.0.1:18320/providers 确认模型类型和名称；不会显示 API 密钥。
3. POST http://127.0.0.1:18320/reindex 可为旧概括重新建立向量。
4. 如果模型不可用，原话仍保留；向量检索失败则退回原有检索。
5. API Key 不放进源码或共享文件；远程 HTTP 明文默认被拒绝（远程用 HTTPS）。
6. 如果配置 GOLDFISH_LOCAL_TOKEN，所有金鱼 HTTP API 请求需带相同的 X-Goldfish-Token 头；DSH 插件侧也需配置。

隐私说明：配置云端 LLM 后，整理任务会将原始聊天内容发给该云端模型；配置云端 Embedding 后，向量化时会将摘要和搜索问题发给云端。未配置模型时，金鱼不会自动向任何模型发送内容。

七、目前的验证边界

已实际调用云端 DeepSeek flash，固定版本 DSH core host 的自动注入、真实助理回答和压缩均已测试。仍未在你的电脑上验收，也未实测 Ollama；其适配目前只有协议测试。不同模型的语义判断质量和延迟需要重新测量，不能沿用 DeepSeek 分数。

八、v0.2.1 接入与可靠性修正

模型接口现在不自动跟随 HTTP 重定向；请直接填写最终接口 URL。错误仅记录类别或 HTTP 状态，不输出原始模型响应。API Key 继续通过环境变量设置。
后台整理完成一轮后自动排队，并连续处理积压批次；失联时原文与游标保留，后台退避重试，重启后自动继续。关闭服务会等待当前模型请求/事务结束，最久可能受模型请求超时影响（整理请求当前为60秒）。

Ollama 适配仍属于协议支持；云端真实结果见第九、十节，不能据此推断本地中文模型质量。

推理前查询向量请求会使用短超时（默认最多1.5秒，并给插件留下回退时间）；超时会继续字面/主题/时间/图关系召回。批量向量索引仍可等待45秒，整理模型请求60秒。慢本地模型首次冷启动可能暂时只用基础召回，后续真实性能调参属于阶段 C。

九、真实DeepSeek评测（2026-11-04）

当前环境已实际调用官方 https://api.deepseek.com 的 deepseek-flash，结果及失败案例在 docs/PHASE_B.md。仍未实测本地Ollama；DeepSeek聊天模型不能当Embedding模型使用，Embedding继续单独配置。

新增可选配置：
GOLDFISH_LLM_THINKING=enabled 或 disabled；留空遵从提供方默认。OpenAI-compatible端点必须实际支持thinking字段，未配置时不发送；Ollama对应think开关。
GOLDFISH_LLM_MAX_TOKENS=8192；留空遵从提供方默认。兼容接口使用max_tokens，Ollama使用options.num_predict。

DeepSeek官方文档当前默认启用思考；本次正式比较显式关闭思考并固定输出上限。仅当明确配置相应Provider与端点时联网。密钥从安全的运行环境设置，不写进命令历史、源码或报告。配置后重新启动服务。
接口参考：https://api-docs.deepseek.com/api/create-chat-completion

十、第三阶段：语义覆盖、少量关键经历与关系复核

沿用上述同一套本地/云端 LLM 配置，另外显式设置：

Bash: export GOLDFISH_SEMANTIC_RECALL=1
PowerShell: $env:GOLDFISH_SEMANTIC_RECALL="1"

重启金鱼后，DSH 的 agent/pre-step 会自动调用 /recall，不需要 Agent 使用记忆工具。
此开关默认为0；未开启时仍为原有词法/时间/主题及可选Embedding路径。
开启云端语义召回会将查询、候选记忆和 DSH 当前有效上下文一并发送给该 LLM，包括压缩摘要；请按自己的数据使用约束配置端点。

语义模型通常选择最多3条关键经历。每条覆盖判断必须给出原记忆片段及上下文逐字证据；完整覆盖抑制，部分覆盖只补来源中的缺失片段，证据无效或不确定则保守保留。逐字引用校验只能证明来源，不能证明模型的语义判断必然正确。
服务语义请求最多10秒；插件默认timeoutMs=12000，预留回退时间。超时会回退基础召回，故可能再次注入改写后已覆盖的事实。慢本地模型可能频繁回退，需在真实设备观察，不能用协议测试证明质量。

GOLDFISH_RELATION_REVIEW 默认1：整理提出关系后，再以两端原话审查类型及证据。设为0可关闭额外调用，但未复核关系不会参与扩散。原始提议不被覆盖，模型自评置信度不等于已校准概率或人工确认。
DSH 插件 depth 默认0；1、2仅用于显式试验。第三阶段实测扩散增加判断Token，未证明稳定收益，所以没有开启默认扩散。

实际DeepSeek用量、延迟、冻结新集、失败及复现命令见 docs/PHASE_C.md。
