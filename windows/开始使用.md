# 将第四阶段安装到你的 Windows 电脑

这是从 Codex Cloud 导出的源码交付，不表示已安装到你的电脑。建议 Windows 10/11、64位、至少8GB内存。首次需联网下载 Python依赖、DSH及约91MB的固定BGE模型。DeepSeek API单独计费；本地Embedding不调用云端Embedding。

## 按顺序操作

1. 安装 **64位 Python 3.11 或 3.12**（python.org，安装时勾选Python Launcher和Add Python to PATH），安装 **Node.js 24 LTS，至少24.9**（nodejs.org）。安装后重开文件夹窗口。无需管理员权限安装金鱼。
2. 下载ZIP，右键“全部解压”，放到固定目录，例如 `C:\GoldfishMemory`。不要从ZIP内部直接运行。后续不要移动或删除该目录：DSH插件链接到这里。
3. 打开 `windows` 文件夹，双击 **Check.cmd**。看到Python、Node、npm版本后继续。失败时先完成上一步，不要反复安装。
4. 双击 **Install.cmd**。等待依赖、模型和隔离DSH下载完成。首次可能数分钟；网络失败可重新运行，已有配置不会覆盖。模型按固定revision及SHA256校验，不从聊天内容生成假向量。首次初始化仅新建隔离profile，不覆盖已有profile。
5. 双击 **Configure.cmd**，在隐藏输入提示中输入DeepSeek API key并回车。密钥由Windows当前账户加密保存在用户目录，不写入项目。不要在config.json里填写API key。
6. 双击 **Start.cmd**。看到“Goldfish ready”后才继续。此窗口可关闭，两个Python后台服务仍运行。
7. 双击 **Chat.cmd** 启动独立DSH Web profile；按终端提示打开本机页面。在DSH模型选择/连接设置中选择 **DeepSeek API key连接**及 `deepseek-flash`。脚本向该进程提供 `DEEPSEEK_API_KEY`；DSH默认的 `deepseek-official` 登录连接可能仍需独立登录或改为API连接，**金鱼的整理模型配置不会自动替换DSH主模型连接**。DSH界面/认证的个人Windows流程尚未验收，以当前固定版本的界面提示为准。
8. 先用虚构经历测试，例如：“2025年我把红伞借给小林，编号RS-17。” 等一轮整理完成，再另开会话问“RS-17借给谁了？” 不要一开始导入重要私人历史。用 **Diagnose.cmd** 检查摘要数量是否增长。
9. 结束时先关闭DSH界面及其终端，再双击 **Stop.cmd** 停止金鱼后台服务。停止过程中中断的整理依靠已保存原话在重启后恢复；不要在进程运行时拷贝或删除数据库。

这些.cmd只是启动PowerShell脚本。若Windows下载拦截，先确认来源及SHA256，再在ZIP属性中“解除锁定”并重新解压。企业策略禁止PowerShell时，请由管理员按组织规则处理；脚本不修改全局执行策略。

## 文件保存在哪里

在资源管理器地址栏输入 `%LOCALAPPDATA%\GoldfishMemory`：

- `config.json`：非密钥模型配置；可用记事本修改，之后Stop再Start。
- `deepseek-key.xml`：Windows DPAPI账户加密凭据，只适用于同一Windows账户/电脑，不能作为跨电脑迁移密钥文件。
- `memory.sqlite3`：私人记忆原文与概括；`*.backup-*` 为启动/迁移前SQLite一致性备份。
- `models`：本地模型；`venv`、`tools`：独立Python与DSH依赖。
- `dsh`：独立DSH home/profile，包含聊天和outbox。不会使用或删除日常DSH目录。
- `*.stdout.log`、`*.stderr.log`：本地运行日志。不要把用户目录、数据库、outbox、聊天或完整日志传到GitHub。

要备份：先关DSH并Stop，再复制整个此用户数据目录到自己的安全位置。备份可能包含私人原话；凭据文件跨电脑不可直接恢复。项目目录与用户数据目录分离，升级源码前保留两者备份。

## 模型与费用

默认示例为DeepSeek云端LLM + 本地BGE-small-zh-v1.5，混合精排显式开启，方便本阶段实聊。它会向DeepSeek发送整理原话、候选记忆以及覆盖判断所需的有效上下文。此安装示例是你的实测选择，**项目默认仍保留legacy**，第四阶段没有证明Embedding全面更好。

- 关闭新方案：config.json内 `GOLDFISH_RETRIEVAL_MODE` 改为 `legacy`；如不需要LLM精排/覆盖，`GOLDFISH_SEMANTIC_RECALL` 改为 `0`。只开Embedding不等于具备语义去重。
- 其他本地/云端Embedding、Ollama、其他LLM：按根目录 `MODEL_SETUP.txt` 配置。两套provider/model/url完全独立。更换Embedding时同时修改revision，重新启动以重建。
- 其他提供方的密钥请用当前PowerShell进程环境变量设置（不要写进项目或配置示例）；这些双击脚本优先服务默认DeepSeek方案，其他主聊天连接由DSH独立配置。
- 默认URL 18321会启动随包CPU模型服务；改用Ollama或其他端点时，Start不会启动这个服务，需要你先启动实际模型服务。

## 出问题时

双击 **Diagnose.cmd**：检查环境、18320后端、18321模型、providers和记忆条数。它不会打印保存的密钥或原始聊天。安装下载失败通常是网络/代理问题；沿用你的正常网络代理与证书，不关闭TLS验证。端口占用时脚本不会杀别的程序。

“有聊天但无摘要”：确认Start成功、Configure已保存有效API key、DeepSeek余额与模型配置正确，查看memory.stderr.log中的错误类别。Diagnose的providers只能证明配置，不能证明实际API认证成功。DSH没自动注入：先确认隔离goldfish-test已加载插件及18320健康，再确认之前的经历已经整理为摘要。

如果修改过本地HTTP鉴权token或模型名，需自行让两端配置一致；默认安装示例不设置本地token，只监听loopback。不要把服务端口开放到公网。

## 卸载与迁移

先关闭DSH终端，再运行 **Uninstall.cmd**。卸载只停止匹配PID/创建时间的金鱼服务，删除本次安装的venv、tools及金鱼保存的加密key。**保留模型、配置、数据库、备份、日志和DSH聊天**。DSH界面自行保存的其他凭据也在保留的dsh目录内；如果要彻底清除个人数据，先自己备份，再手动删除用户数据目录。卸载不会删除云端项目，也不改你的日常DSH安装。

完整第四阶段报告：`docs/PHASE_D.md`。已在Cloud验证Python、固定DSH宿主、真实BGE和DeepSeek；**Windows脚本、Windows依赖安装、浏览器DSH认证、你的硬件性能和私人实聊均未在你的电脑验证**。
