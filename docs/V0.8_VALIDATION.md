# v0.8.0 验证范围与已知问题

本页公开汇总结果，不附原始聊天、真实模型请求/响应日志、个人配置或本机部署快照。旧版本原始评测输出从当前源码树移除；Git 历史保持不变。历史文档 PHASE_A/B/C/D 是早期模型实验阶段，不等同本机升级阶段 B1/B2/C/D/E，当前架构以 README 为准。

## E阶段已有真实模型验收

此前已在同一用户 Windows/DSH 0.2.1-rc.5 环境，以有限虚构语料完成：

- 同一经历跨轮、跨批成为一个事件，事实分别关联原话；同义复述增加证据，不无限生成事实。
- 明确纠正保留旧说法；先前感受和后来意义分别保留历史状态。
- 主要记忆搜索后，DSH自主提出新问题，沿两跳证据关系找到首次搜索未返回的跨主题经历，并查原话。
- 语义相似但用户明确说无关的经历分开；证据不足的关系保持候选；明确否认后撤销并留审计。
- 6156字符消息中位于6100的细节仍可核查；整理中断后同任务恢复。
- 原网页两次真实 /compact 后，新会话能够找回具体经历、标记/存放位置以及用户报告的影响。
- B2 显式保存与后续压缩不重复；无明确授权的 remember 调用仍被拒绝；C指引不进入长期库。

这些是实际主模型/宿主测试，不代表所有模型、所有主题或长期规模已经验证。原模型路线中的 Claude 等其他供应商尚无同等质量结论。

六题/版配对对照的平均端到端：D25.964秒，E26.084秒；主模型逻辑请求32→26，工具调用26→23；含缓存的上下文输入约+3.4%。不能据此宣布更快、更省或普遍更准确。工具查询在毫秒量级，长尾主要发生在模型请求路径；本机代理、网络与远端等待尚不能精确拆分。

## 发布准备的独立验证

重新从 npm 安装固定 DSH，不使用生产 DSH 的 node_modules、凭据、模型或真实数据库。临时 venv 不安装额外 Python 包。新 Windows 安装器在隔离数据目录和独立端口完成安装、schema6启动、更新保留旧记录、卸载保留数据。

- Python146项：143通过、2项既有失败、1项平台跳过。
- Node40项：39通过、1项平台跳过。
- 安装版 DSH 的 B1/B2/C/旧捕获模拟模型宿主回归4项通过。
- 新增原生压缩→真实HTTP/schema6→跨批同事件→逐事实原话集成1项通过；提案/复核由合成模型夹具产生，不是新增真实模型质量验收。

两项 Python 基线失败保留在 `test_service_reliability.py`：

1. `test_real_http_process_auth_idempotency_full_source_and_graceful_exit`：隔离子进程HTTP后端启动失败。
2. `test_sigterm_waits_for_active_manual_http_consolidation`：同类Windows子进程启动/关闭流程未通过。

没有删除或跳过它们来凑全绿；发布独立安装与其他真实HTTP测试已通过，不能替代上述SIGTERM条件的验证。

新增集成测试初版曾4次失败：Cordis `plugin()` 返回Fiber，异步注册还未结束，合成模型就已飞快完成并压缩历史。改为先等待状态工具注册后再开始测试，最终通过；没有修改已验收的核心记忆算法。此次发布准备未额外消耗外部主模型请求。

## 仍然有限的能力

旧D/B2跨不同来源的全面语义归并、旧库自动事件化；超过候选窗口的无漏组织；事件超预算后的自动拆分；更多关系类型通用质量；跨进程多宿主租约；大库、高并发和长期盲评，均未完整验证。

同主模型提案与复核仍可能共同犯错；逐字引用验证的是来源存在，不是独立证明结论一定正确。正式关系不等同已确证的因果。
