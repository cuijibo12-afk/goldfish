## 1. 上下文语义覆盖：按命题补缺

修复前：`_covered` 规范化后检查整段原文是否包含在上下文中。DSH 将事实改写成中文或英文后，即使编号、位置、日期都保留，仍会重新注入；历史注入ID本来就不能证明内容仍在。

修复后：配置相同本地/云端 LLM，显式开启 `GOLDFISH_SEMANTIC_RECALL=1`。模型将记忆拆成原文命题，分别引用有效上下文证据；程序校验原文引用、上下文引用及整条记忆的信息覆盖。完整覆盖抑制；部分覆盖只补原记忆中缺失的片段；缺失、冲突、不确定分别保留。不能用置信分数或ID替代引用。引用校验只能验证来源，语义蕴含仍是可能出错的模型判断。

## 3. 关系类型：保留原提议，另外记录有效复核

修复前：保留理由、端点证据和模型置信度，但模型提议的类型可能直接进入扩散。共享一个物件曾被写成同事件；理由承认身份不明的边也可参与图检索。

修复后：`link_reviews` 增量表保存 supported/rejected/uncertain、有效规范类型、理由、双方逐字来源、模型身份与输入hash。原提议不覆盖；来源或端点改变使复核失效。只有有效受支持边或明确人工/用户确认边可扩散。确定不重合的事件日期强制否决 same_event。`contrast` 历史别名只映为 comparison，不当作 contradiction。

旧36条关系的实际模型复核为 **31 supported、5 uncertain**；这些都不是人工确认。已知失败对照：

| 原边 | 修复前 | 修复后 |
| --- | --- | --- |
| `c1bf63b9-07ff-42be-908e-1ee9a3cb78d9` | 2024赠蓝布袋与2026再次使用，same_event，自评0.95 | 有双方“同一个袋子”原话，改为same_entity；不再以same_event扩散 |
| `acafb4e5-447a-4774-94aa-e7fc4b5a8752` | 理由说不清是否同一次活动，仍same_event | uncertain；不参与扩散 |

## 6. 云端/本地兼容、运行方式与验证

仍共用 `GOLDFISH_LLM_*` 选择 Ollama 原生或 OpenAI-compatible 本地/云端；Embedding另配，不绑定DeepSeek。云端只访问明确配置的地址，不跟随重定向。语义调用在DB锁外，失败不阻断原文入库和主对话。

本轮实际探测本机 Ollama `127.0.0.1:11434/api/tags` 和 LM Studio `127.0.0.1:1234/v1/models` 均不可连接。因此**真实本地模型未验证**；本地协议自动测试继续保留，不能拿它们替代实测。未下载模型，未改用户日常profile。

启用语义路径需在已有LLM配置之外设置 `GOLDFISH_SEMANTIC_RECALL=1` 并重启Python；云端会收到查询、候选和当前有效上下文。默认关系复核 `GOLDFISH_RELATION_REVIEW=1`，可设0关闭额外调用，未复核边不扩散。插件默认12秒、语义请求最多10秒，图深度0。真实评测使用30秒语义超时，本次全部查询最大7.34秒、DSH两组最大2.70秒；未触发线上10秒界限，但不代表所有本地设备满足该时限。
