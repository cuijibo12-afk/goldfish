# 第二阶段：真实 DeepSeek 与中文记忆质量验证

日期：2026-11-04。实际模型为官方 API 返回的 `deepseek-flash`，端点为 `https://api.deepseek.com`。保留 Python / SQLite / Provider / DSH 生命周期架构。本阶段没有增加 GUI、记忆工具或外围服务产品。

本阶段完成了真实调用、可重复评测和若干核心修复；**没有据此宣布记忆质量已完全达标**。尚未解决的主要问题是跨时间比较的检索排序、关系类型混淆，以及压缩摘要改写后的语义去重。

## 测试材料与方法

- 离线语料为人工编写的虚构中文对话：8 会话、64 消息、6467 字符，包含 26 个事实、6 个画像、12 个参考关系和24个查询。包括 fixture 中的助手台词在内，均不是用户私人历史。实际提取、概括、主题和关系输出来自真实 DeepSeek HTTP 响应。
- 另在真实 DSH `0.2.1-rc.5` core 宿主运行四组各六轮聊天；这些组的助手回复、自动整理和压缩摘要也来自真实 DeepSeek，没有使用合成回复替代。
- 比较使用实际基线输入的固定快照 [chinese_memory_cases.baseline.json](../evals/chinese_memory_cases.baseline.json)，SHA-256 为 `8f26f516f5f33cce1248181e416a7c12f2ee46fa4d736f74903ae1b4613d0b0c`。原语料作者最后的 source 标签及部分允许背景修改与基线启动交错，另一份 `chinese_memory_cases.json` 保留为不同版本；下表全部使用同一 baseline 快照，未换用更宽松的标注提高分数。
- 正式离线调用统一 `thinking=disabled`、`max_tokens=8192`，无 Embedding。模型名是服务端滚动别名；记录 response ID 和用量不能锁定权重版本。接口文档说明非思考模式有服务端固定采样规则，不能因请求传了 temperature=0.1 就宣称输出确定。
- 词面/证据探针只是可审核代理指标。同义改写、拆成多条概括、未标注但有用的内容列为待复核。`unknown` 不算错误，也不自动算正确。q06/q08/q10/q14 的标注争议另外列在语料说明中，未事后改金标准。
- 逐条证据复核由 Codex 完成，**不是独立真人审定**；保留原始输出供用户复核。

## 实际结果

全部试验与计量见 [summary.json](../evals/results/deepseek-flash-2026-11-04/summary.json)。没有只保留较好的一次。

| 运行 | 整理通过 | 事实词面探针 | 召回事实探针 | 明确禁止项命中 / 未裁决返回项 | 实际 Token | 提取延迟 P50 / P95 |
| --- | --- | --- | --- | --- | --- | --- |
| baseline：原提取提示词 | 7/8 | 23/26 | 20/29 | 9 / 53 | 30,995 | 9.23 / 11.05 秒 |
| after：第一轮修复 | 8/8 | 23/26 | 21/29 | 2 / 52 | 31,611 | 6.60 / 10.78 秒 |
| final：协作结果、主题复用修复 | 8/8 | 22/26 | 20/29 | 8 / 51 | 32,229 | 5.93 / 8.41 秒 |
| final-repeat：同提取参数与提示词复测 | 8/8 | 21/26 | 20/29 | 9 / 53 | 33,114 | 6.91 / 8.28 秒 |
| validated：本阶段最后的提取实现 | 8/8 | 23/26 | 21/29 | 3 / 45 | 33,241 | 6.00 / 8.66 秒 |

另外将同一64条消息合并成一个跨年长期会话，真实模型按 **14、14、14、14、8** 条处理了5个批次，全部成功且游标无剩余；得到35条概括、11个主题、35条关系和20条画像，实际用了27,015 Token。它检查真实长会话分批整理与跨批关联，不是新的盲测样本，也不能证明更长上下文或个人长期质量。[单会话实测](../evals/results/deepseek-flash-2026-11-04/long-session/metrics.json)

因此不能声称修复后“整体质量稳定提升”。验证拒绝已修好，主题复用和预算结果保留有明确改善，但检索结果仍受模型拆分方式和抽样变化影响。最终召回探针为 **72.4%**；8 个未命中目标中有 4 个存在待复核候选，不能把所有未命中当作真正语义遗漏。已判定返回项的 precision 为 33/36（91.7%），但还有45项未知；该数不能当成总体准确率。按全部81条返回计算的保守区间为40.7%–96.3%。

最终产生33条具体概括、10个复用主题、36条关系、21条画像。对照基线为36条概括、33个几乎逐条新建的主题、48条关系、39条画像。主题数量下降只是辅助证据，具体细节是否保留仍由原文与概括逐条对照。[最终原始记忆](../evals/results/deepseek-flash-2026-11-04/validated/memory.json)包含实际概括、主题成员、边理由、置信度和证据ID。

模型调用期间的Token均使用服务端 `usage`。全阶段104个有计量的真实响应共报告 **308,062 Token**，包含失败的提取、调试和复测；另有2次无模型响应的网络失败，无法推断其计费，不按零费用计算。首次未限制思考的两次排错分别用了7453和7650 Token；后续显式关闭思考。没有货币费用估算。

最终本地24问检索延迟 P50/P95 为2.90/5.76毫秒，不含提取、网络或Embedding。默认真实DSH六轮主答共9459 Token、累计8.79秒；一次真实压缩3447 Token、4.71秒；7次自动整理13563 Token、9.92秒。这些是模型请求耗时，不能当作完整交互延迟。注入长度只计字符，未用字符数冒充Token。

## 具体案例

**跨年、跨主题的一组经历：** q01 提到“左下角橙色补丁、铜拉链的袋子”，召回2024年父亲修好收音机赠送蓝布袋、2026年社区修理日再次带去同一袋子的两段具体经历；q18 还召回用户自己表达的“修理结束像父亲解释接触不良、觉得踏实”的联系。日期、物件特征和感受没有被压成一个“家庭”主题。[逐问注入](../evals/results/deepseek-flash-2026-11-04/validated-final-retrieval/recalls.json)

**协作结果与行为画像：** s05 原模型把仅有 assistant 证据的行为放入 summaries，导致整个批次在验证阶段被拒绝，没有部分写入。修改后共同引用用户单价更正与助手计算原话，保留180元/分钟、4320元的旧版本及160元/分钟、3840元的新版本；录音棚、后期仍未知。实际行为写为本次预算中的列缺项、计算及更正，没有存“天生冷静毒舌”或“永远可靠”。q15 已召回最终金额及未知项。[模型原始提取](../evals/results/deepseek-flash-2026-11-04/validated/model_calls.json)

**画像分类与召回：** “不要因为是用户就附和”存 interaction_expectation；“上一条标签太机械”存 feedback；2023年以来带路打印纸图存 user_profile；本次预算改算存 ai_observed。最终还有一条 feedback 的类别边界需复核，且“不要将天生性格自称当事实”的反馈没有以预期证据完整单独保留。历史全职岗位、日历提醒的画像缺明确观察日期，仍可能与后来的变化混淆。不能仅因未出现错误人格就宣称整个分类场景满分。

**负查询：** 基线问冰岛火山“原因”，仅凭这个泛词召回了个人工资、录音机等5条经历。检索现在过滤泛问句线索，此案不再注入个人记忆。画像也改为按查询相关性排序，修复新医疗画像挤掉旧交互期望/纸图习惯；最后一处类别回退打平相关分数的问题，用同一真实输出数据库零API调用重放验证，6个预期画像查询目标命中从3增到5。[最终检索重放](../evals/results/deepseek-flash-2026-11-04/validated-final-retrieval/report.json)

## 关系证据与真实失败

最终36条边均有理由、合法置信度、端点和原话证据，全部仍为未确认的 `model_hypothesis`，没有生成 `causal_confirmed`。置信度是模型自评，未经过校准。

Codex逐条证据复核将31条列为主要依据支持、3条为弱假设、2条为关系类型错误：

- `acafb4e5-447a-4774-94aa-e7fc4b5a8752`：理由承认未明确同一次活动，却标为 same_event。
- `c1bf63b9-07ff-42be-908e-1ee9a3cb78d9`：同一蓝布袋跨两年出现在不同事件中，被标成 same_event，混淆“同一物件”与“同一事件”。

这是关系类型质量问题；“有证据ID、没有确认因果”不足以证明关联正确。[逐条复核](../evals/results/deepseek-flash-2026-11-04/validated/codex_source_review.json)

图扩展对最终24问的事实探针命中由20增至21，但明确禁止项由2增至3、未知项由31增至45。已有收益也有噪声，不能笼统宣布图扩展优于关闭。[深度0与2对照](../evals/results/deepseek-flash-2026-11-04/validated/metrics.json)

另外的未修好案例：q03 比较去年拒绝插画与今年接受音频项目时，检索仍会把预算报价、合同续约等条目排在照护/周转金条件变化之前，关键经历遗漏；画像时效和较长概括挤占1800字符预算也仍有影响。

## 真实 DSH 主对话与压缩

全部继续使用 `agent/pre-step` 自动注入，未注册记忆工具。自动整理持续开启，逐轮等待原文游标推进，没有冻结数据库隐藏重复概括。

- 修复前真实测试发现旧反馈或正常回复行为被写成新画像，五轮中出现额外注入。进一步限制普通本轮指令/普通复述不升级画像、反馈须与当前查询有关。
- 最后真实运行五轮新增注入为 **1、0、0、0、0**，6轮助手回复与12条采集记录对应；全部7次自动整理完成，没有把注入存成用户原话。[完整真实链路记录](../evals/results/deepseek-flash-2026-11-04/dsh-live-validated-lossy/report.json)
- 默认原生压缩测试中，真实摘要保留了同行人、饮品、FJ-7315、票夹在笔记本里等事实；金鱼下一轮仍重复注入完整概括。这是**已确认的语义去重失败**，不能拿结构检查全过冒充去重成功。[失败复核](../evals/results/deepseek-flash-2026-11-04/dsh-live-final/codex_compaction_review.json)
- 另做明确标注的有损压力场景：原生 `compactNow()` 和真实模型不变，但额外要求摘要只留主题、最后一轮不复述细节。实际压缩后5项线索消失；金鱼下一轮全部补回，模型实际答出“FJ-7315，蓝色地铁票夹在纸质笔记本里”。这验证真实缺口恢复，**不代表默认DSH压缩必然丢这些信息**。

## 代码、复现与验证范围

核心改动：`consolidate.py` 约束来源/协作结果/画像范围/时间精度/主题复用；`engine.py` 修正泛词误召回、双时间线索、画像相关性和反馈筛选，并把现有主题提供给提取模型；`providers.py` 支持显式思考/输出预算与真实usage计量。没有更换数据模型或聊天模型架构。

运行方式见 [evals/README.md](../evals/README.md) 和 [DSH真实模型复现](DSH_LIVE_MODEL.md)。新增评测在缺少明确配置时不伪造成功，也不会自动换成别的模型。当前没有可用Ollama或LM Studio服务，本地配置及协议回归保留，**本地真实模型未实测**；本阶段没有进行真实Embedding评测，也没有使用用户私人长对话。

最终本地回归：Python73项、Node13项及原DSH综合集成1项通过；已有测试中的合成模型仍只是回归，不计作上面的真实质量结果。所有带密钥的调用结束后删除临时凭据文件；源码、评测文件和Git提交均检查不含该密钥。下一步核心工作应优先解决语义覆盖判断、关系类型和跨时间排序，再扩大真实用户对话样本；本次结果尚不能替代个人长期使用验收。
